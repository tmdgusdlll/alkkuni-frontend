# PROGRESS.md

알꾼이 프론트엔드의 진행 상황이다. **작업 PR 안에서 갱신하고, 머지되면 확정된다.** 머지 후 문서만 고치는 변경을 만들지 않는다.

- PR을 올리기 전: 작업 커밋에 결정 이유, 다음 할 일 정리 등 이미 아는 내용을 넣는다.
- PR을 올린 뒤 머지 전: PR 번호는 PR 생성 후 첫 커밋(보통 `/code-review` 반영 커밋)에 함께 넣는다. 반영할 게 없을 때만 번호 커밋을 따로 한다.

섹션:

- 지금 상태: 화면 단위 목차. 체크 안 된 첫 항목이 다음 작업이다. 해당 PR에서 체크한다.
- 다음 할 일: 지금 작업에서 정할 것과 검증 기준. 끝난 항목은 지우고 "완료"에 날짜와 함께 옮긴다.
- 작업 로그: 결정과 그 이유. 최근 날짜가 위에 온다.

전체 계획(작업 단계, 화면·API 결정)은 백엔드 `docs/PLANNING.md`, `docs/PROGRESS.md`에 있다. 프론트에서 정한 것만 여기 적고, 백엔드 계획이 바뀌어야 하면 백엔드 PR로 고친다.

### 2026-11-11

- 성분별 제품 목록 (`feat/explore`)
  - 조건(성분·제외·제형·함량 범위·기준 충족·정렬·페이지)을 모두 URL에 두고 GET `<form>`과 `<Link>`로만 바꾼다. 클라이언트 컴포넌트가 없다. 성분 추가는 `<select name="ingredient">`이고 이미 고른 성분은 hidden으로 다시 보내 뒤에 붙는다. 빈 select·없는 id·중복·6개째는 `parseParams`가 버린다(제출 URL에 `exclude=&min=`처럼 빈 값이 남지만 무시됨).
  - 성분 사전(215개)을 매 요청 함께 부른다. 칩 이름, 기준값 유무("기준 충족" 체크박스를 끄고 이유를 적음), 함량 범위 단위에 쓴다. 범위 단위는 `defaultUnit` → `referenceUnit` → 결과의 `dailyUnit` 순(기준값 없는 성분 161개는 앞의 둘이 null).
  - 기준 성분(함량순·함량 범위가 걸리는 성분)이 바뀌는 링크(칩 빼기, 정렬 바꾸기)는 함량 범위를 비운다. 다른 성분의 값·단위로 그대로 걸리면 뜻이 바뀐다. 고르지 않은 성분 기준 정렬(`amount:999`)은 에러 대신 기본 정렬로 본다.
  - 막대는 기준 성분 열에만, 이 페이지의 최댓값 대비다. 오류 의심(상한 2배 초과)·다른 단위·1일 함량 모름 값은 막대와 최댓값 계산에서 뺀다(아연 첫 행 80.64mg 검수 대기가 최댓값이면 나머지 막대가 모두 짧아짐). 기준치 대비는 막대 없이 "기준치 N%" 글자로(성분 열이 여러 개라 `DvProgress`를 쓰면 표가 너무 넓어짐).
  - 표는 가로 스크롤 상자 + 제품명 열 고정(DESIGN.md 6.2). 표 안 "표시 기준량" 배지는 설명을 펼치지 않는다(`BasisBadge explain={false}`). 펼친 설명이 스크롤 상자에 잘려서, 설명은 옆 안내의 배지 범례에 둔다.
  - 4xx(최솟값 > 최댓값 등)는 백엔드 문구와 "고른 성분만 남기고 조건 지우기" 링크. 필터 폼은 그대로 보여 바로 고칠 수 있다.
  - 공통으로 뺀 것: `Pagination`(검색과 같이 씀), `AmountBar`, `OtherUnitBadge`(상세와 같이 씀). 헤더에 "성분 비교" 메뉴를 달았다. 활성 표시(`aria-current`)는 현재 경로가 필요해 클라이언트 컴포넌트가 되므로 메뉴가 늘 때 붙인다.
  - 확인(로컬 백엔드 데이터): 아연+마그네슘 1,801개, 기준 충족 85개, 최소>최대 문구, 루틴(기준값 없음) 체크박스 꺼짐·단위 mg, 엽산 다른 단위 표기, 페이지 500(10001위부터), 잘못된 sort·exclude·form·min 무시, 폼 제출로 성분·제형 추가, 390px 표 가로 스크롤·필터 줄바꿈, 처음 화면. `npm run lint`, `npm run build` 통과.

- 검색 화면 (`feat/search`, PR #2)
  - `/code-review` 반영: 함량은 소수 6자리까지 보여준다(백엔드가 μg을 mg으로 바꿔 B12 0.0006mg이 기본 3자리면 "0.001"·"0"이 됨). 마지막 페이지를 넘은 `page`는 "첫 페이지로" 링크, 정렬 에러(`details[0].field == "sort"`)는 "관련도순으로 보기" 링크. "표시 기준량" 설명은 `title` 대신 `<details>`로(터치·키보드로 열림). `api()`에 10초 타임아웃, 검색창 `minLength={2}`(백엔드 최소 길이). 결과는 쿼리를 key로 한 `<Suspense>` 안에 둬서 정렬·페이지 이동 때도 "불러오는 중"이 보인다.
  - `cacheComponents`가 켜져 있어 `searchParams`는 `<Suspense>` 안의 컴포넌트에서 읽는다. 바깥 틀은 빌드 때 미리 만들어지고 결과만 요청 때 채워진다(빌드 결과 `/search`가 ◐ Partial Prerender).
  - 검색어·정렬·페이지를 URL에 둬서 클라이언트 컴포넌트 없이 만들었다. 검색창은 `<form action="/search">`, 정렬·페이지는 `<Link>`. 클라이언트 컴포넌트는 에러 경계(`error.tsx`) 하나뿐이다. 이 Next 버전의 에러 경계는 `reset`이 아니라 `retry`를 받는다.
  - `api()`는 백엔드 에러 본문(`INVALID_INPUT` 등)을 `{ error }`로 돌려주고, 백엔드가 꺼져 있거나 JSON이 아니면 예외를 던진다. 앞은 화면에 백엔드 문구(`details[0].reason`)를 그대로, 뒤는 `error.tsx`가 "불러오지 못했어요"를 보여준다.
  - 검색 응답에는 기준값·주 단위가 없어 기준 대비 %·"다른 단위 표기"는 검색 화면에 두지 않는다(목록·상세에서 보여줌). 1일 함량이 없으면 "함량 확인 필요".
  - 성분 이름 뒤 조사("비타민 C이")는 받침에 따라 달라 붙이지 않았다.
  - 데이터 기준일을 주는 API가 없어 푸터에는 출처만 뒀다.
  - 실제 데이터로 확인(Playwright): `비타민C` 함량순(배지 두 종류), `아연` 함량순, `크롬` 마지막 페이지(1일 함량 없음 3건), `종근당`(함량·함량순 숨김), `q=C`·`종근당&sort=amount`(백엔드 문구), 없는 검색어, 잘못된 `page`, 백엔드 중지(에러 화면).
  - 제품 이미지가 공공데이터에 없어 결과 행 왼쪽에 제형(`form`) 아이콘을 둔다(`FormIcon`, DESIGN.md 5). 원문 제형 12종을 도형 7개로 묶고, 없거나 모르는 제형은 가장 흔한 정제로 그린다. 제형은 옆에 글자로 있어 아이콘은 `aria-hidden`이다. 상세·목록·비교에서도 쓴다.
  - 상한 초과 경고: `아연` 함량순 1위 90mg(상한 35mg의 2배 초과)이 경고 없이 보였다. 판정은 비교·상세 응답에만 있고 검색에는 없었다. 프론트가 상한을 따로 받아 계산하면 "판정은 백엔드" 원칙이 깨져 백엔드 검색 응답에 `exceedsUpperLimit`을 더했다(백엔드 `feat/search-upper-limit`). 상위 3개(90, 80.64, 80mg)에 "검수 대기"가 붙는 것을 확인했다.
  - 검색 결과 수가 띄어쓰기에 따라 다르다(`비타민C` 9,042개, `비타민 C` 7,523개). 성분은 둘 다 `비타민 C`로 잡히니 제품명 유사도 쪽 차이로 보인다. 화면 문제가 아니라 기록만 한다.

  - CORS를 백엔드에 넣지 않았다. 브라우저는 같은 출처 `/api`로만 부르고, 로컬은 Next rewrites, 운영은 Nginx가 api로 넘긴다. 서버 컴포넌트는 `API_URL`로 백엔드를 직접 부른다(서버끼리라 CORS 무관). 다른 도메인에서 API를 부를 일이 생기면 그때 넣는다.
  - `NEXT_PUBLIC_` 환경 변수는 쓰지 않는다. `next build` 때 값이 박혀 이미지 하나로 환경을 바꿀 수 없다.
  - 디자인 기준은 사용자 초안 PNG(`../../alkkuni-docs/프론트 초안/`)와 그걸 바탕으로 Claude 디자인이 만든 문서다. 생성 문서는 백엔드 코드를 보지 않고 만들어져 API와 맞지 않는 곳을 고쳤다: `PER_SERVING`을 "표시 기준량당"으로 반대로 정의, 지어낸 타입(IU 환산, 회수일·공지 링크, 구매 링크, 구조화된 기능성), 성분 비교가 한 화면(`/explore`와 `/compare?ids=`로 나뉘었음). 타입은 백엔드 DTO를 그대로 옮긴다.
  - 소셜 로그인은 OAuth 경로(`/oauth2/authorization/*`, `/login/oauth2/code/*`)가 `/api` 밖이라, 로그인 작업 때 rewrites·Nginx에 경로를 추가하고 각 콘솔의 리다이렉트 URI를 다시 본다.
